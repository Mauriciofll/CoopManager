# Tutorial de uso do CoopManager

Este tutorial foi feito para orientar o uso do CoopManager no dia a dia da cooperativa. A ideia do aplicativo é ajudar o intermediador a organizar produtos, produtores, clientes e pedidos, sem substituir a conversa com os produtores, a conferência física dos itens ou a tomada de decisão da equipe.

O CoopManager não é um sistema de vendas completo, caixa, ERP ou loja virtual. Ele funciona como um ajudante operacional para acompanhar o que foi pedido, o que o produtor enviou, o que a cooperativa recebeu e quais pendências precisam de atenção.

## 1. Como abrir o aplicativo

No computador, abra o CoopManager pelo atalho instalado ou pelo arquivo:

```
CoopManager.exe
```

Se for a primeira abertura em uma instalação zerada, o aplicativo mostra a tela Primeiro acesso. Nessa tela, crie o primeiro administrador informando nome, login, senha e confirmação da senha. Esse usuário será usado para entrar no sistema e cadastrar os demais produtores, clientes e informações da cooperativa.

Depois que o primeiro administrador existir, a tela inicial passa a pedir login e senha. Após o acesso, o aplicativo mostra as principais abas de trabalho:

- Resumo
- Produtos
- Usuários
- Clientes
- Pedidos

## 2. Perfis de usuário

O aplicativo trabalha com dois tipos principais de uso.

### Administrador ou intermediador

É o perfil da pessoa que organiza a operação. Esse usuário pode cadastrar produtores, clientes, acompanhar pedidos, registrar recebimentos, verificar divergências e consultar listas de trabalho.

Use este perfil para:

- Cadastrar e revisar produtos.
- Cadastrar clientes.
- Criar pedidos.
- Conferir itens recebidos na cooperativa.
- Acompanhar atrasos, pendências e divergências.
- Consultar listas de produtor, conferência e separação.

### Produtor

É o perfil usado por quem fornece produtos para a cooperativa. O produtor vê e movimenta principalmente os próprios produtos.

Use este perfil para:

- Cadastrar ou atualizar produtos próprios.
- Consultar pedidos que envolvem seus produtos.
- Informar se enviou todos os itens solicitados ou apenas parte deles.
- Registrar observações quando houver alguma pendência.

## 3. Tela Resumo

A aba Resumo serve como painel de atenção. Ela mostra informações importantes para o intermediador agir sem precisar procurar pedido por pedido.

Nessa tela, observe principalmente:

- Pedidos atrasados.
- Pedidos previstos para hoje.
- Itens aguardando envio do produtor.
- Itens enviados, mas ainda não recebidos pela cooperativa.
- Divergências entre quantidade enviada e quantidade recebida.
- Produtos com estoque baixo.

Quando aparecer uma pendência, use a aba Pedidos para ver o detalhe e registrar a ação necessária.

## 4. Cadastro de produtos

A aba Produtos organiza o catálogo operacional da cooperativa.

Para cadastrar um produto:

1. Abra a aba Produtos.
2. Preencha o nome do produto.
3. Informe a categoria, quando disponível.
4. Informe o preço.
5. Informe o estoque atual.
6. Informe o estoque mínimo, se quiser receber alerta de baixo estoque.
7. Salve o cadastro.

Para alterar um produto já cadastrado, dê duplo clique no item da tabela. Isso evita editar por acidente e deixa mais claro quando a pessoa está criando um produto novo ou alterando um existente.

Um produtor logado consegue gerenciar apenas os produtos dele. O administrador consegue consultar e acompanhar todos.

Importante: quando um produto já aparece em pedidos, o aplicativo evita excluir esse cadastro para preservar o histórico.

## 5. Cadastro de clientes

A aba Clientes guarda as pessoas ou empresas que fizeram pedidos.

Para cadastrar um cliente:

1. Abra a aba Clientes.
2. Preencha o nome.
3. Informe telefone, endereço ou observação, se for útil para a operação.
4. Salve o cadastro.

Para alterar um cliente já cadastrado, dê duplo clique no item da tabela.

Assim como nos produtos, clientes que já aparecem em pedidos não devem ser excluídos, pois fazem parte do histórico da operação.

## 6. Cadastro de usuários e produtores

A aba Usuários é usada para administrar quem acessa o sistema.

Use essa tela para cadastrar:

- Administradores ou intermediadores.
- Produtores da agricultura.
- Produtores do artesanato.
- Outros perfis definidos pela cooperativa.

Cada produtor deve ter seu próprio usuário. Isso ajuda o aplicativo a mostrar apenas os produtos e pedidos que fazem sentido para aquela pessoa.

Para alterar um usuário, dê duplo clique no item da tabela.

## 7. Criação de pedidos

A aba Pedidos é a área principal para acompanhar a operação.

Ao criar um pedido, preencha apenas as informações necessárias para registrar a solicitação e acompanhar a movimentação dos produtos. Em geral, o mais importante é:

- Cliente do pedido.
- Produto solicitado.
- Quantidade.
- Preço do produto.
- Data prevista, se houver.
- Observação, quando necessário.

Depois de criado, o pedido passa a ser acompanhado por item. Isso é importante porque um pedido pode ter produtos de produtores diferentes, e cada item pode estar em uma etapa diferente.

## 8. Envio pelo produtor

Quando o produtor separar os produtos para enviar à cooperativa, ele deve registrar o envio no pedido.

Na aba Pedidos:

1. Selecione o pedido.
2. Selecione o item do pedido.
3. Veja a próxima ação disponível.
4. Se todos os produtos daquele item foram enviados, mantenha marcada a opção Todos enviados.
5. Se apenas parte foi enviada, desmarque Todos enviados.
6. Informe a quantidade exata enviada.
7. Adicione observação se houver motivo para envio parcial.
8. Clique para aplicar a ação.

Exemplo: se o pedido solicitou 10 cestas e o produtor só conseguiu enviar 7, ele deve registrar envio parcial de 7 unidades. Assim o intermediador sabe que ainda faltam 3 unidades e pode investigar ou combinar uma solução.

## 9. Recebimento pela cooperativa

Quando os produtos chegarem fisicamente à cooperativa, o administrador ou intermediador deve registrar o recebimento.

Na aba Pedidos:

1. Selecione o pedido.
2. Selecione o item recebido.
3. Veja a próxima ação disponível.
4. Se tudo que foi enviado chegou corretamente, mantenha marcada a opção Todos recebidos.
5. Se chegou apenas parte do que foi enviado, desmarque Todos recebidos.
6. Informe a quantidade exata recebida.
7. Escreva uma observação explicando a diferença.
8. Aplique a ação.

Quando a quantidade recebida for menor que a quantidade enviada pelo produtor, o aplicativo marca uma divergência. Essa divergência serve como alerta para a equipe investigar o que aconteceu, por exemplo erro de contagem, perda no transporte, produto danificado ou registro incorreto.

## 10. Etapas do pedido

O pedido pode passar por etapas como:

- Aguardando produtores.
- Aguardando recebimento.
- Parcialmente recebido.
- Pendência.
- Em separação.
- Pronto.
- Entregue.
- Cancelado.

O usuário não precisa decorar todas as etapas. O aplicativo mostra a próxima ação útil de acordo com o estado atual do pedido e com o perfil logado.

Evite mudar etapas sem registrar o que aconteceu de fato. O objetivo do histórico é ajudar a equipe a entender o caminho do pedido.

## 11. Observações e histórico

Sempre que houver algo fora do padrão, use o campo Observação.

Exemplos de observações úteis:

- Produtor enviou apenas parte por falta de estoque.
- Produto chegou com quantidade menor que a enviada.
- Cliente pediu para retirar em outra data.
- Item aguardando confirmação do produtor.
- Pedido cancelado por solicitação do cliente.

Essas observações aparecem no histórico operacional e ajudam a evitar dúvidas depois.

## 12. Listas operacionais

Dentro da área de Pedidos, a aba Listas ajuda a organizar o trabalho fora da tela.

As listas podem ser usadas para:

- Ver o que cada produtor ainda precisa enviar.
- Conferir itens que chegaram à cooperativa.
- Separar produtos por cliente.
- Copiar informações para mensagem, impressão ou conferência manual.

Use os filtros antes de gerar a lista se quiser focar em um período, status, produtor ou tipo de pendência.

## 13. Filtros

Os filtros servem para encontrar rapidamente o que precisa de atenção.

Filtros úteis no dia a dia:

- Aguardando produtor.
- Em trânsito.
- Com divergência.
- Atrasados.
- Previstos para hoje.
- Prontos para separação.
- Baixo estoque.

Se a tela parecer com informações demais, comece por um filtro de situação. Isso reduz a lista e deixa mais fácil decidir a próxima ação.

## 14. Uso no celular

O CoopManager também possui uma versão mobile adaptada para celular.

Ela pode ser usada de duas formas:

- Pelo navegador, como PWA.
- Pelo APK Android de teste.

No celular, a navegação fica na parte inferior da tela e as ações principais aparecem em botões maiores, próprios para toque. Em uma instalação nova, o mobile também abre uma configuração inicial para criar o administrador local. A versão mobile é útil para registrar movimentações rápidas, consultar pedidos e acompanhar listas operacionais.

Importante: no estado atual, o mobile usa armazenamento local do próprio aparelho. Ele começa sem dados de demonstração e ainda não sincroniza automaticamente com o banco do desktop.

## 15. Instalação do APK Android

Para instalar a versão APK:

1. Envie o arquivo `CoopManager-Mobile-debug.apk` para o celular Android.
2. Abra o arquivo no celular.
3. Se o Android pedir permissão, libere instalação de apps desconhecidos para o aplicativo usado para abrir o APK.
4. Confirme a instalação.
5. Abra o CoopManager na tela de aplicativos.

O APK atual é uma versão de teste. Para distribuição oficial, será necessário gerar uma versão assinada para release.

## 16. Boas práticas de uso

- Cadastre produtos com nomes claros.
- Mantenha o estoque atualizado.
- Use observações sempre que houver divergência ou envio parcial.
- Não exclua cadastros ligados a pedidos antigos.
- Registre envio somente quando o produtor realmente separou ou despachou o produto.
- Registre recebimento somente depois da conferência física.
- Consulte o Resumo no início do dia para identificar prioridades.
- Use as listas operacionais para apoiar conferência, separação e comunicação.

## 17. Fluxo recomendado no dia a dia

1. O administrador confere o Resumo.
2. Produtores atualizam produtos e estoque quando necessário.
3. O administrador registra novos pedidos.
4. Cada produtor informa envio total ou parcial dos seus itens.
5. A cooperativa confere fisicamente os itens recebidos.
6. O administrador registra recebimento total ou parcial.
7. Divergências são investigadas com base no histórico.
8. A equipe usa as listas para separar e acompanhar a entrega ou retirada.
9. O pedido é finalizado quando tudo estiver resolvido.

## 18. Dúvidas comuns

### O aplicativo faz venda automaticamente?

Não. Ele registra e acompanha pedidos como apoio operacional, mas não substitui negociação, pagamento, emissão fiscal ou entrega.

### O produtor consegue ver produtos de outros produtores?

Não no fluxo normal. O produtor acessa principalmente os próprios produtos e os itens de pedido ligados a ele.

### O que fazer quando o produtor enviou menos do que o pedido?

Registrar envio parcial e informar a quantidade enviada. Se necessário, adicionar observação.

### O que fazer quando a cooperativa recebeu menos do que o produtor disse que enviou?

Registrar recebimento parcial e informar a quantidade recebida. O aplicativo marcará a divergência para investigação.

### Posso excluir um produto que já apareceu em pedido?

O aplicativo evita essa exclusão para preservar o histórico. O recomendado é manter o cadastro e ajustar estoque ou informações quando necessário.

### O mobile sincroniza com o desktop?

Ainda não. A versão mobile atual é um apoio local/offline. A sincronização automática pode ser uma evolução futura.

### Quais são os logins iniciais?

Na versão zerada não existem logins prontos. O primeiro login é criado pela própria cooperativa na tela Primeiro acesso.

### Dá para usar em vários computadores ao mesmo tempo?

Sim, mas precisa de uma configuração inicial. A forma mais simples é escolher um computador principal da cooperativa para guardar os dados e instalar nele o PostgreSQL. Depois, os outros computadores são configurados para acessar esse computador principal.

Para a equipe, depois de configurado, o uso continua normal: cada pessoa abre o CoopManager, faz login e trabalha nos mesmos pedidos. Para instalar e testar isso com calma, siga o guia [Banco compartilhado do CoopManager](BANCO_COMPARTILHADO.md), que foi escrito em formato passo a passo e explica até qual versão do PostgreSQL baixar e o que marcar no instalador.
